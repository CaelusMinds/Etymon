# Review: is Etymon on point?

> Status 2026-10-05: review of `0.1.0-preview.14` against the question Etymon
> was built to answer, the F# ecosystem, and the four consumers. Verdicts and
> actions below; the owner decides the business rulings in the last section.
> Deliberately not done: no code was changed by this review, and no
> recommendation here is adopted until a dated design note records the design.

## The question

Etymon exists because the owner asked which things the F# community needs that
no library offers, and, where a library does offer one, what would make the
thing better. Etymon is consumed today by Keel, FlowQL and Mast (applications
and the platform library) and by Windlass (a tool). The question this review
answers, package by package: unmet need filled, or offered elsewhere and done
better, or offered elsewhere and done the same or worse, or failing Etymon's
own admission test — "does the package derive something from a Schema? If not,
it is not Etymon, however good it is" (`docs/decisions.md`).

## The answer

Measured against the question Etymon was built to answer, the fifteen packages sort as follows. Two fill a need offered nowhere else: Etymon.Core (accumulating errors carrying a nested path, with constraints kept as data that other derivations read) and Etymon.Schema.Compatibility (an in-process stored-event and wire check derived from the codec's own Schema). Two do an offered job better: Etymon.Schema and Etymon.Schema.OpenApi carry the constraint list and the optional-versus-nullable distinction from one definition into every document without reflection. One fills a need nobody else fills, with deficits: Etymon.Schema.TypeScript emits in-process from an F# Schema at request time, and no compiler has ever read the output in CI. Two fill a need only on paper or half-built: Etymon.Api (zero consumers) and the typed harness in Etymon.Invariants.FsCheck (no shrinker). One matches the alternative: Etymon.Invariants. One trades strengths with no possible consumer in the suite: Etymon.Api.Giraffe. Five do an offered job the same or worse, all with zero first-party consumers: Etymon.Schema.Sql, Etymon.Config, Etymon.Api.AspNetCore, Etymon.Api.Client and the Etymon meta-package. One fails Etymon's own admission test: Etymon.Base. The four packages every product consumes are the four that pass, and the defects worth a release sit inside those four.

**Grades.** Critical: a verdict or output a product relies on is wrong today, in that product's suite. High: a defect or gap worth a release, including code a product duplicated or patched in its own repository against the ruling that a defect is fixed in Etymon. Medium: worth a design note. Low: polish. Each action states what is wrong today, or that the defect is latent and why.

## Package by package

### Etymon.Core — unmet need, Etymon fills it (partially)

- Nearest alternative: Validus 4.1.4 with FsToolkit.ErrorHandling 5.2.0 (F#); FSharp.Domain.Validation; AdCodicem.ValueObjects 0.2.1 (C#, source-generated, same rule-once thesis) (https://github.com/pimbrouwers/Validus)
- The alternative lacks: Validus errors are a flat Map<string, string list> (Core.fs) with no nested path; validators are closures, so a min length cannot be read back; FsToolkit's Validation<'a,'err> carries no path; neither has a redacting Secret<'T> or culture-explicit option-returning parsers; AdCodicem reaches EF Core and OpenAPI only, in C#.
- Etymon lacks: Refine, the README headline (Core README.md:43-76), has zero product call sites; Parse inputs are plain string, so a consumer with nullness on gets FS3261 on a string | null (no Nullable in Etymon.Core.fsproj); ErrorReason and Constraint have no stable machine code, so Mast (Validation.fs:28) and Windlass (Verdict.fs:80) spell codes by hand; Secret.fs:19-20 calls a walking comparison a side channel while Equals at :41-47 is ordinary equality.
- First-party consumers: 4 of 4 (Keel 8 files on the error model and Check.opaque plus Secret in 2; FlowQL 13 Check.oneOf and 12 ValidationErrors hits; Mast 12 Path.root, 10 Path.field, 5 Validation.toProblem, Secret in 7 files; Windlass 3 files). Refine: 0.
- Verdict: No F# library pairs accumulating path-bearing errors with constraints other derivations read (verified 2026-10-05 against Validus Core.fs, FsToolkit ce.md, FSharp.Domain.Validation). The fill is partial: Refine unconsumed, Parse refuses nullable strings, no stable codes. Harmed today: Mast and Windlass hand-spell codes; the rest latent. Evidence: Core Surface.fsi:25-148, :262-292, :479-519, :527-597, :1255-1295, :1316-1338.

### Etymon.Schema — offered elsewhere, Etymon does the job better

- Nearest alternative: FSharp.SystemTextJson 1.4.36 (5.6M downloads) plus .NET 9+ System.Text.Json.Schema.JsonSchemaExporter; Thoth.Json (Thoth.Json.Net 12.0.0) for combinator decoders (https://github.com/Tarmil/FSharp.SystemTextJson)
- The alternative lacks: FSharp.SystemTextJson names no constraints, JSON Schema, TypeScript or SQL; JsonSchemaExporter reflects over the CLR type, emits type, required, default and a numbers-as-strings pattern, honors no annotation for minimum or maxLength, and yields no TypeScript or compatibility snapshot; Thoth keeps encoder and decoder as two values with no constraint vocabulary. Only Etymon.Schema gives one value that encodes, decodes, validates and documents (Surface.fsi:98-142), keeps optional distinct from nullable per field (SNullable :123 versus FieldInfo.Required), and feeds six derivations from one SchemaInfo without reflection.
- Etymon lacks: Auto derivation (Schema.auto is prose only); union encodings beyond one adjacent tag with a hard-coded 'value' key (Schema.fs:878-898), so Keel hand-writes an internal-tag codec (Keel.Ledger.Store/EventCodec.fs:69-144); metadata lost below SNullable (SchemaInfo.fs:159-162); no runtime list-driven constructor (FlowQL RowSchema.fs:36-66 folds ObjectPart records); no alias slot (#27); nine document disagreements; Thoth's cross-platform reach; maturity (0 stars at 15 days).
- First-party consumers: 4 of 4 (Keel 29 files, FlowQL 28, Mast 16, Windlass 7; 24 fsproj references in Keel and Windlass). FlowQL's schema.json and types.ts from these Schemas are the one Etymon output read outside the suite (FlowQL Routes.fs:958-966).
- Verdict: The codec is offered elsewhere and the Schema README says so (README.md:10-16). Etymon does the combined job better because constraints and the optional-versus-nullable distinction travel from one definition into JSON Schema, TypeScript, the compatibility snapshot, SQL, Config and generators, which no fetched alternative does, and every product consumes exactly that path. The 'better' is conditional on fixing the SNullable, union, runtime-constructor and alias defects listed under actions. Evidence: Schema Surface.fsi:11-50, :57-96, :98-150; README.md:48-73, :120-139, :156-282.

### Etymon.Schema.OpenApi — offered elsewhere, Etymon does the job better

- Nearest alternative: Microsoft.AspNetCore.OpenApi (OpenAPI 3.1 default in .NET 10, transformers, build-time generation through Microsoft.Extensions.ApiDescription.Server); NJsonSchema 11.6.1 (401M downloads); FSharp.Data.JsonSchema.NJsonSchema 3.1.0 (2026-07-28, F# unions as anyOf with discriminators) (https://learn.microsoft.com/en-us/aspnet/core/fundamentals/openapi/aspnetcore-openapi?view=aspnetcore-9.0)
- The alternative lacks: A document derived from the same value that decodes and validates: every alternative reflects over a CLR type (NJsonSchema reads DataAnnotations the decoder never runs), so document and decoder can drift, while Etymon renders a pure function of SchemaInfo (Surface.fsi:26-45); absent-versus-null kept apart per field without attributes (FSharp.Data.JsonSchema maps options to nullable wrappers); an unrepresentable rule reported in the description rather than dropped (README.md:90-103); toComponentsWithRoot for the array-items $ref trap (Surface.fsi:95-131); no Newtonsoft dependency.

- Verdict: Better on provenance: the document is a function of the value that decodes, not of a type or a host, and the owner's products refuse reflection near payloads (Keel decisions.md:1033-1060, Mast OpenApi.fs:25-29). Worse on coverage: two dialects, no discriminator, no instance validation, no multi-schema entry point. Corrected from round two's draft: ASP.NET's generator also runs host-free at build time, so Etymon's lead is the value, not the absence of a server.
